## Автоматические проверки main

Оба workflow имеют `pull_request` без фильтров веток/путей и `push` с `main`.
Открытие нового PR в `main`, его обновление и последующий push после слияния
запускают проверки. После попадания Unity workflow в default branch доступен
`workflow_dispatch`. Фильтры не требуют изменений для этой интеграции.

.NET и локализация доступны в том числе fork/Dependabot. Unity использует
существующие Secrets только для доверенных PR из того же репозитория;
fork/Dependabot пропускаются и не считаются проверенными Unity.
`pull_request_target` не используется. Общая concurrency group сохраняет
последовательное использование Personal-лицензии.

Это настройка запуска CI, не настройка защиты ветки или обязательности checks.
Отсутствующий Linux-образ явно даёт NOT RUN в summary исходного workflow;
такой запуск не подтверждает сборку. Для этой версии наличие образа проверено.
