## Доказательства и границы диагноза

В job `132320524433` выполнены компиляция, **194 EditMode** и **17 PlayMode**
тестов, XML-барьер и Linux IL2CPP build. Player открывает окно, сохраняет PNG,
после чего Python выдаёт `No bright organism pixels in the world viewport`.
Это ошибка содержимого изображения, а не chmod или невозможность запуска.

В исходниках подтверждены два дефекта конфигурации:

- `PrototypeSetup` включает только `CellPrototype`; проверочная сборка не
  содержит `WaterPrototype3D`, требуемую для текущего 3D-игрового интерфейса.
- Сохранение instancing-вариантов шейдеров было реализовано только в
  `VisualPreviewBuild`, а IL2CPP `BuildLinux` его не вызывал. Оба рендера
  создают instanced-материалы во время исполнения; анализ сцены не обнаруживает
  такое использование и может удалить нужные варианты при сборке.

Без открытия исходного PNG нельзя окончательно отличить влияние stripping
от особенностей чтения X11 framebuffer. Лог подтверждает точку отказа,
но не доказывает конкретный цвет/содержимое кадра. Исходный артефакт:
https://github.com/evgenijzingaev-dev/Evolution/actions/runs/43553340637/artifacts/14097564870

## Изменение

Настройка графики общая для обоих способов сборки; IL2CPP остаётся IL2CPP.
Включена 3D-сцена вместе с прежней. Только явный аргумент Visual Preview
переключает проверочный player на неё; обычный запуск сохранён.

Player Capture сначала запускает существующий `WaterVisualPreview` и его
валидатор на этом же IL2CPP player. Камера URP действительно рендерит кадры;
PNG читаются из её render target или игрового framebuffer после end-of-frame.
Проверяются настоящие организмы, глубина, ресурсы, навигация, HUD, версия,
ревизия, ошибки шейдеров и разрешения 1366×768 / 1920×1080 / 2560×1440.
Затем без удаления прежних проверок выполняется исходный smoke-тест
`CellPrototype` с X11, мышью, клавиатурой и порогом яркости организмов.

Лицензии и сырые Editor/player logs не добавляются к артефактам.
Core, игровая биология и визуальный стиль этим исправлением не изменяются.
